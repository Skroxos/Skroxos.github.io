The Philosophy

TechSandbox is not a game project. It serves as a strict engineering environment for prototyping complex logic away from the clutter of a main project. The goal is simple: avoid "MonoBehaviour hell" and build pure, modular C# systems.

Every module here is built with the intention of being scalable, memory-safe, and easily injectable into any future project using Dependency Injection.

Core Implementations

  • Zero-GC Event Bus: A high-performance messaging system utilizing generic static routing and struct constraints to completely eliminate heap allocation (boxing).
  • Spatial Hash Grid: O(1) optimized math-based grid for resolving proximity queries (e.g., finding nearby enemies) without relying on expensive Unity Physics colliders.
  • MVP Inventory System: A fully modular crafting and inventory system built strictly on the Model-View-Presenter pattern, keeping UI completely decoupled from data.
  • Dependency Injection (VContainer): Systems are wired up using DI, ensuring single-responsibility classes and easy unit testing without Singleton abuse.
  • Async Workflows: Using UniTask for non-blocking API mock calls and Addressables for memory-safe asynchronous asset loading.

Architecture Snippets

A quick look at how the core systems are structured, focusing on performance and readability.

1. Zero-GC Event Bus (Struct Routing)


public static class EventBus
{
    // C# creates a unique class per T at compile time.
    // O(1) routing, no dictionaries, no boxing.
    private static class EventContainer<T> where T : struct, IEvent
    {
        public static Action<T> OnEvent;
    }

    public static void Publish<T>(T eventData) where T : struct, IEvent
    {
        EventContainer<T>.OnEvent?.Invoke(eventData);
    }
}

2. Spatial Hashing Grid Math


public int GetCellIndex(Vector3 worldPos)
{
    // Fast O(1) grid positioning without Physics bounds
    int x = Mathf.FloorToInt(worldPos.x / _cellSize);
    int z = Mathf.FloorToInt(worldPos.z / _cellSize);  

    x = Mathf.Clamp(x, 0, _gridWidth - 1);
    z = Mathf.Clamp(z, 0, _gridHeight - 1);

    return x + (z * _gridWidth);
}

3. Dependency Injection (VContainer)


public class GameLifetimeScope : LifetimeScope
{
    protected override void Configure(IContainerBuilder builder)
    {
        // Core Logic
        builder.Register<InventoryModel>(Lifetime.Singleton);
        
        // MVP Pattern Wiring
        builder.Register<InventoryPresenter>(Lifetime.Scoped);
        builder.RegisterComponentInHierarchy<InventoryView>();
    }
}

4. UniTask & Addressables Integration


public async UniTask<GameObject> SpawnEntityAsync(string key, CancellationToken token)
{
    // Zero-alloc async/await avoiding Coroutine overhead
    var handle = Addressables.InstantiateAsync(key);
    var instance = await handle.WithCancellation(token);
    
    // Inject into Object Pool...
    return instance;
}

Engineering Takeaways

Building these systems in isolation has fundamentally improved how I approach C# within Unity. By stepping away from standard Unity tutorials and studying compiler behavior (like generic monomorphization for the Event Bus) or data-oriented design (Spatial Hashing), I am now able to write code that respects CPU cache and minimizes Garbage Collector spikes.

This sandbox is proof that I don't just "make games work" — I engineer them to run efficiently.
